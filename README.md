## 2. Task & Calibration Summary
- **Bug 1 (Easy):** `main()` hardcodes `Path("transactions.csv")` instead of validating `sys.argv[1]` and exiting non-zero when the CLI argument or input file is missing.
- **Bug 2 (Medium):** `reconcile()` counts every non-`FAILED` status (including `PENDING`) as `VALID` instead of summing `Decimal` amounts for `VALID`, counting `FAILED`, and ignoring all other statuses.
- **Bug 3 (Hard):** `reconcile()` compares `timestamp` strings lexicographically with `>` instead of parsing ISO-8601 `datetime` instants across timezone offsets and breaking same-instant ties in favor of the later row (`>=`).
- **Calibration Scores:** `nop` = `0.00` | `oracle` (`solve.sh`) = `1.00` | Partial `oracle` (Bug 1+2 fixed, Bug 3 broken) = `0.50` | `hack.sh` = `0.00` (`1.00` against the naive static binary verifier)

## 4. Trajectory Forensics (`trajectory.json`)
- **Where the Agent Failed in Run 1:** In `reconcile-bug__yGjvEEG`, step 4's failed patch proposed lexicographic string comparison and used a `+00:00`-only test; step 5 actually wrote the string-comparison logic and reran that single-offset test. In `reconcile-bug__yGZcrXj`, step 3's later-row tie-rule patch used raw string `>` or `==` and failed; step 4 actually wrote that logic and tested only `Z` rows. Only `reconcile-bug__aJ55uZt` parsed real `datetime` objects in step 4 and passed.
- **Ablation Hypothesis & Result:** The hypothesis was that placing a mixed-timezone `sample_transactions.csv` inside `/app` would encourage cross-offset testing instead of single-timezone toy CSVs, and I selected Ablation B. The controlled change coincided with a pass-rate increase from `1/3` in Run 1 to `3/3` in Run 2; this is not universal causal proof. In `reconcile-bug__GF8pCow`, step 3 wrote raw string-timestamp comparison and step 4 ran it on the sample to get `80.0`, before step 6 switched to real `datetime` objects and got `42.45` (similarly, `reconcile-bug__aEnMz4C` stripped `tzinfo` in step 4 and got `80.0` on the sample before converting aware `datetime` objects to UTC in step 6 to get `42.45`). Because `3/3` gives `0.000` advantage across all trials, `sample_transactions.csv` was removed afterward. The final environment matches Run 1, while the final verifier is intentionally dense.

## 5. Dense Reward & Anti-Cheat Design
- **My Dense Reward Weights (`tests/test.sh`):** Split `0.00` to `1.00` across three weighted checks: `0.20` (Bug 1: CLI validation), `0.30` (Bug 2: status filtering), and `0.50` (Bug 3: cross-timezone deduplication and tie-breaking), weighting Bug 3 highest since it was the check that split Run 1. Because every check invokes `python3 /app/reconcile.py <csv_path>` via `run_and_parse` (asserting exit code `0` and valid JSON), Bug 1's CLI path handling gates all three checks; once CLI invocation works, Check 2 (`PENDING`/`CANCELLED`/`EXPIRED` filtering on unique UTC-`Z` IDs) and Check 3 (cross-timezone deduplication and same-instant ties using only `VALID`/`FAILED` rows) are orthogonal. At verification time, `nop` scores `0.00`, `oracle` scores `1.00`, and partial `oracle` (Bug 1+2 fixed, Bug 3 broken) scores `0.50` as predicted.
- **How `solution/hack.sh` Cheated & How I Blocked It:** `solution/hack.sh` overwrote `/app/reconcile.py` with a fixture-fingerprinting stub that checks CLI arguments and matches the three static CSV payloads from the Option-1 binary verifier (`"25.50,VALID"` -> `25.5 / 1 / 0`, `"99.99,PENDING"` -> `10.3 / 2 / 1`, and default -> `45.25 / 2 / 1`) without parsing CSV rows or timestamps—scoring `1.00` on the naive static verifier. `tests/test.sh` blocks this by generating randomized test CSVs with random filenames in a temporary directory at grading time and computing expected outputs using an internal reference function, scoring `hack.sh` at `0.00`.
- **Remaining Reward-Hacking Risk:** From AI's shared-container risk analysis (which also noted reading `/tests/test.sh` to invoke `reference_reconcile`, poisoning `sitecustomize.py`/`python3`, or writing `1.00` to `/logs/verifier/reward.txt` and sending `SIGKILL` to the verifier process), I selected the background-watcher / process-tampering risk: because the agent runs as `root` in the shared container, it can leave a background watcher or runtime hook that kills `test.sh` or overwrites `/logs/verifier/reward.txt` with `1.0`. Proposed mitigation: grade in a fresh isolated container (`verifier.environment_mode = "separate"`) that receives only the submitted `/app/reconcile.py`, so no agent processes or runtime modifications survive into grading.

## 6. AI Tool Workflow
- **AI Tool & Model Used:** Antigravity with Gemini 4 Hydrogen (XHigh) and Gemini 4 Neon (XHigh) wrote repo code and ran Harbor jobs (with full and compact parent session transcripts and subagent transcripts exported under `ai_transcripts/`). For Harbor evaluations, the final reported baseline and ablation used `terminus-2` with `groq/openai/gpt-oss-120b`, `k=3`, `n=1`. AI drafted the initial `instruction.md` in the main chat from the business rules before bug selection. After I chose the three bugs from the AI's tier options, raised `agent.timeout_sec` from `120` to `240` seconds, and supplied the initial binary-verifier checklist, the main chat updated `instruction.md` and implemented the initial `tests/test.sh`, while delegating `environment/reconcile.py` and the initial `solution/solve.sh` to a separate subagent (`ai_transcripts/subagents/implementation.jsonl`). After the first Groq baseline scored `3/3` (`hSUeRtg`, `UGnCNNK`, `Gkp8SFn`), I chose Option 1; the main chat updated `instruction.md` and delegated `solution/solve.sh` and `tests/test.sh` tie-rule updates to a second subagent (`ai_transcripts/subagents/tie_rule.jsonl`) without changing the planted environment bug. Because the main chat proposed the bug tiers, wrote the subagent prompts, and updated `instruction.md` at those checkpoints, those edits were manually checked for spoiler-free phrasing rather than context-isolated. The later trajectory, grader, and math work remained collaborative: AI supplied early Run 1 trajectory summaries and binary advantages; I verified the trajectories, chose Ablation B, supplied the `GF8pCow` reading, set the `0.20 / 0.30 / 0.50` weights, predicted the `0.50` partial-oracle score before running it, and supplied the checked advantage table. Early `/tmp` directories for the quota-stopped Gemini run, the initial `3/3` Groq run, and the Option-1 binary calibration runs were not retained after `/tmp` cleanup; the Run 2 binary `nop`/`oracle` calibration jobs (`calib-run2-nop`, `calib-run2-oracle`), `run1-baseline`, `run2-ablation`, `verify-dense-*`, and `rescore` are preserved in `jobs/` and `jobs_summary/`.
- **How I Avoided Prompt Leakage:** The initial pre-bug `instruction.md` draft stated that timestamps are `"compared in absolute UTC time across timezones"`. In its bug-tier analysis, the AI warned that explicit UTC comparison wording could make bare string-timestamp comparison too obvious; after bug selection, that phrase was softened to `"(representing the latest point in time across timezones)"`. When the first Groq baseline still scored `3/3` (with `2/3` trials using strict `>`), the AI identified that the parenthetical timezone hint still telegraphed Bug 3. I then selected Option 1: remove the timezone hint completely and add the same-instant/later-CSV-row tie rule (`"keep only the row with the latest timestamp; on ties, keep the row that appears later in the file"`), bringing Run 1 into the `1/3` Goldilocks zone.
